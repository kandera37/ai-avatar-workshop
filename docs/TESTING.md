Дата: 17 ноября 2026 года. Локальная среда: Windows, Node.js 26.10.0. CI настроен на Ubuntu и Node.js 24. Платных внешних запросов при подготовке не выполнялось.

- `npm test`: **81 тест**, 81 passed, 0 failed, 0 skipped.
- `npm run test:ui`: полный сценарий Playwright, **14 локальных mock-вызовов**, без внешнего image API.
- Синтаксис: server.js, ai-adapter.js, db.js, src/*.js, public/*.js, scripts/*.js и tests/*.js.
- `npm run check:public`: проверка состава и текстовых шаблонов секретов. Дополнительно перед публикацией проверены исключённые идентификаторы, изображения и чистая история Git.

Сессии и права на версии; базовый prompt и ограничения; генерация и multipart edit; ошибочные payload; таймауты; invalid_request; авторизация провайдера; safety reject; резервная модель; раздельное health state, cooldown и half-open; очистка active lock после ошибки; авторизация ведущего; постоянные public/developer/quest бюджеты; гонка за последнюю единицу; учёт fallback; отказ до provider при нулевой квоте.

QUEST API: Bearer, server-only access, русский prompt, необязательный style, idempotency, конфликт тела, очередь и ограничения, completed/failed, растровый imageUrl, TTL, ошибки провайдера, восстановление после перезапуска без повторения начатой задачи.

Подтверждены: игнорирование случайно унаследованного AI-ключа в demo, реальный HTTP generate, сохранение последней картинки и счётчика после рестарта, сохранение кода ведущего. Проверяются ошибки выполнения JavaScript.

## Реальная демонстрация

`npm run capture` запускает Express и Chromium, выполняет создание → улучшение до версии 02 → публикацию, затем открывает галерею и панель ведущего. Скриншоты в docs/images получены этим способом. GIF — запись того же браузерного сценария, без подмены страниц.

Вызовы модели в этих проверках заменены локальным fixture. Изображения синтетические, описание не изменяет их художественное содержимое. Проверка подтверждает приложение, HTTP-путь и сохранение данных; она не измеряет качество или скорость Quanteex.

## Не проверялось

Новые реальные генерации или edit через платный API, текущий тариф и наличие моделей у провайдера, массовая нагрузка, многопроцессное развёртывание, внешняя инфраструктура и юридическое соответствие конкретного детского мероприятия.

Для платного smoke-test нужен собственный ключ, явный connected-режим и отдельный ненулевой бюджет. Автоматические тесты не требуют этого доступа.
